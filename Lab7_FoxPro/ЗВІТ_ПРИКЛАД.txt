2.5. РЕАЛІЗАЦІЯ АЛГОРИТМУ ПОШУКУ
---------------------------------
Реалізовано метод DoSearch() для послідовного пошуку:

ПСЕВДОКОД:
```
FUNCTION DoSearch(SearchValue, FieldName, CaseSensitive)
    SCAN  // Цикл по всіх записах
        FieldValue = EVALUATE(FieldName)

        IF CaseSensitive
            // Порівняння з урахуванням регістру
        ELSE
            FieldValue = UPPER(FieldValue)
            SearchValue = UPPER(SearchValue)
        ENDIF

        IF SearchValue $ FieldValue  // Пошук підрядка
            RETURN .T.  // Знайдено!
        ENDIF
    ENDSCAN

    RETURN .F.  // Не знайдено
ENDFUNCTION
```

ОСОБЛИВОСТІ РЕАЛІЗАЦІЇ:
- Використано команду SCAN для перегляду всіх записів
- Оператор $ для пошуку підрядка
- Функція UPPER() для регістронезалежного пошуку
- Можливість пошуку наступного збігу

5.1. Метод Init головної форми:
```foxpro
PROCEDURE Init
    SET DEFAULT TO (JUSTPATH(SYS(16)))
    CLOSE DATABASES ALL

    IF FILE("data\lab_7_db.dbc")
        OPEN DATABASE data\lab_7_db SHARED
        USE customer IN 0
    ELSE
        DO data\create_database.prg
        OPEN DATABASE data\lab_7_db SHARED
        USE customer IN 0
    ENDIF

    DO menus\mainmenu.mpr WITH THISFORM, .T.
    RETURN .T.
ENDPROC
```

5.2. Метод пошуку:
```foxpro
FUNCTION DoSearch(tcSearchValue, tcFieldName, tlCaseSensitive)
    LOCAL lcFieldValue, lcSearchValue, llFound
    llFound = .F.

    SCAN
        lcFieldValue = EVALUATE("customer." + tcFieldName)

        IF VARTYPE(lcFieldValue) != "C"
            lcFieldValue = TRANSFORM(lcFieldValue)
        ENDIF

        IF tlCaseSensitive
            lcSearchValue = tcSearchValue
        ELSE
            lcFieldValue = UPPER(ALLTRIM(lcFieldValue))
            lcSearchValue = UPPER(ALLTRIM(tcSearchValue))
        ENDIF

        IF lcSearchValue $ lcFieldValue
            llFound = .T.
            EXIT
        ENDIF
    ENDSCAN

    RETURN llFound
ENDFUNC
```

7. ВІДПОВІДІ НА КОНТРОЛЬНІ ПИТАННЯ
=========================================

1. Що таке послідовний пошук?
   Послідовний пошук - це алгоритм пошуку, який переглядає
   кожен елемент масиву/таблиці по черзі від початку до кінця,
   поки не знайде потрібний елемент або не досягне кінця.

2. Яка складність алгоритму?
   O(n), де n - кількість записів у таблиці.
   В найгіршому випадку потрібно переглянути всі записи.

3. Які переваги послідовного пошуку?
   - Простота реалізації
   - Не потребує сортування
   - Працює з будь-якими даними
   - Можна шукати по будь-якому полю

4. Які недоліки послідовного пошуку?
   - Повільний для великих таблиць
   - Неефективний порівняно з бінарним пошуком
   - Завжди O(n) складність

5. Як працює команда SCAN?
   SCAN перебирає всі записи таблиці від поточної позиції
   до кінця. Всередині циклу можна обробляти кожен запис.
