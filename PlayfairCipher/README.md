Реалізація шифру Плейфера для українського алфавіту з використанням C++ та Windows Forms.

## Опис алгоритму шифру Плейфера

### Історична довідка

Шифр Плейфера (Playfair Cipher) був винайдений Чарльзом Уітстоном у 1854 році, але названий на честь барона Плейфера, який популяризував його використання. Це один з перших шифрів, що працює з парами літер (біграмами), а не з окремими символами.

### Принцип роботи

#### 1. Побудова матриці шифру

Для українського алфавіту використовується матриця **4×8** (32 клітинки):

```
Український алфавіт: АБВГДЕЄЖЗІЙКЛМНОПРСТУФХЦЧШЩЮЯҐЇ (32 літери)
```

**Приклад з ключовим словом "УКРАЇНА":**

```
У К Р А Ї Н Б В
Г Д Е Є Ж З І Й
Л М О П С Т Ф Х
Ц Ч Ш Щ Ю Я Ґ
```

**Алгоритм побудови:**
1. У матрицю спочатку записуються літери ключового слова (без повторень)
2. Потім додаються решта літер алфавіту (які не входять у ключ)
3. Матриця заповнюється зліва направо, зверху вниз

#### 2. Підготовка тексту

Перед шифруванням текст обробляється:
- Видаляються всі символи крім українських літер
- Текст переводиться у верхній регістр
- Якщо дві однакові літери стоять поруч, між ними вставляється літера **'Г'**
  - Приклад: "ПРИВІТ" → "ПРИВІТ" (без змін)
  - Приклад: "АННА" → "АНГНА" (між НН вставлено Г)
- Якщо довжина тексту непарна, в кінець додається літера **'Я'**
  - Приклад: "ПРО" → "ПРОЯ"

#### 3. Правила шифрування

Текст розбивається на пари літер (біграми). Для кожної пари застосовуються наступні правила:

**Правило 1: Літери в одному рядку**
```
Приклад: ПР (П і Р в одному рядку)
Дія: Зсув вправо на одну позицію (циклічно)
П → С, Р → Т
Результат: ПР → СТ
```

**Правило 2: Літери в одному стовпці**
```
Приклад: УГ (У і Г в одному стовпці)
Дія: Зсув вниз на одну позицію (циклічно)
У → Г, Г → Л
Результат: УГ → ГЛ
```

**Правило 3: Літери утворюють прямокутник**
```
Приклад: УР (різні рядки і стовпці)
Дія: Заміна на літери з того ж рядка, але з протилежних кутів
У (рядок 0, стовпець 0) → Р (рядок 0, стовпець 2)
Р (рядок 0, стовпець 2) → У (рядок 0, стовпець 0)
Результат: УР → РУ (обмін стовпцями)
```

#### 4. Дешифрування

Дешифрування виконується зворотніми операціями:
- **Правило 1**: Зсув вліво (замість вправо)
- **Правило 2**: Зсув вгору (замість вниз)
- **Правило 3**: Обмін стовпцями (операція симетрична)

## Приклади використання

### Приклад 1: Просте шифрування

**Ключове слово:** КИЇВ

**Матриця:**
```
К И Ї В А Б Г Д
Е Є Ж З Й Л М Н
О П Р С Т У Ф Х
Ц Ч Ш Щ Ю Я Ґ
```

**Відкритий текст:** ПРИВІТ

**Підготовлений текст:** ПРИВІТ (6 літер - парна кількість, змін не потрібно)

**Біграми:** ПР ИВ ІТ

**Шифрування:**
1. **ПР** - різні рядки/стовпці → обмін стовпцями → **РП**
2. **ИВ** - в одному рядку → зсув вправо → **ЇК**
3. **ІТ** - різні рядки/стовпці → обмін стовпцями → **ТІ**

**Зашифрований текст:** РП ЇК ТІ

### Приклад 2: Обробка однакових літер

**Ключове слово:** УКРАЇНА

**Відкритий текст:** АННА

**Підготовлений текст:** АНГНА (вставлено 'Г' між НН)

**Біграми:** АН ГН А_

**Примітка:** Оскільки залишилась одна літера 'А', додається 'Я' → АНГ НАЯ

**Біграми:** АН ГН АЯ

### Приклад 3: Дешифрування

**Ключове слово:** КИЇВ

**Зашифрований текст:** РП ЇК ТІ

**Дешифрування:**
1. **РП** - різні рядки/стовпці → обмін стовпцями → **ПР**
2. **ЇК** - в одному рядку → зсув вліво → **ИВ**
3. **ТІ** - різні рядки/стовпці → обмін стовпцями → **ІТ**

**Відкритий текст:** ПРИВІТ

## Особливості реалізації

### 1. Підтримка українського алфавіту

```cpp
ukrainianAlphabet = L"АБВГДЕЄЖЗІЙКЛМНОПРСТУФХЦЧШЩЮЯҐЇ";
```

Алфавіт містить **32 літери**:
- Без літер: **Ь, Ъ, Ы** (застарілі)
- З літерами: **Є, І, Ї, Ґ** (специфічні українські)

### 2. Матриця 4×8

```cpp
rows = 4;
cols = 8;
matrix = gcnew array<array<wchar_t>^>(rows);
```

Матриця має **4 рядки** та **8 стовпців**, що дає рівно **32 клітинки** для всіх літер українського алфавіту.

### 3. Обробка тексту

```cpp
String^ PrepareText(String^ text)
{
    // 1. Видалення не-букв

    // 3. Вставка 'Г' між однаковими літерами
    // 4. Додавання 'Я' для непарної довжини
}
```

### 4. Кодування UTF-8 BOM

## Переваги та недоліки

### Переваги шифру Плейфера

✅ **Простота реалізації** - алгоритм легко зрозуміти та реалізувати
✅ **Стійкість до частотного аналізу** - шифрування біграм ускладнює аналіз частоти окремих літер
✅ **Компактність** - потрібна лише матриця 4×8 та ключове слово
✅ **Історична цінність** - один з перших біграмних шифрів

### Недоліки шифру Плейфера

❌ **Слабка криптостійкість** - сучасні методи криптоаналізу легко зламують цей шифр
❌ **Обмеження** - працює лише з буквами одного алфавіту
❌ **Зміна довжини тексту** - додавання 'Г' та 'Я' змінює оригінальний текст
❌ **Втрата інформації** - після дешифрування потрібно вручну видаляти додані символи

## Криптографічна оцінка

### Простір ключів

Для українського алфавіту (32 літери):
- Кількість можливих ключів: **32! ≈ 2.6 × 10³⁵**
- На практиці, якщо ключ - слово з 8 літер: **32⁸ ≈ 1.1 × 10¹²**

### Атаки на шифр

1. **Частотний аналіз біграм** - аналіз частоти пар літер в тексті
2. **Відомий відкритий текст** - якщо є пара (відкритий текст, шифртекст), можна відновити матрицю
3. **Brute force** - перебір усіх можливих ключів (не практично для 32!)

### Сучасне застосування

⚠️ **Шифр Плейфера НЕ є криптографічно стійким!**

Використовується лише в **навчальних цілях** для вивчення:
- Базових принципів криптографії
- Історії шифрів
- Алгоритмів заміни

Для реального захисту даних використовуйте:
- **AES** (Advanced Encryption Standard)
- **RSA** (для асиметричного шифрування)
- **Сучасні бібліотеки:** OpenSSL, Crypto++

## Troubleshooting (Вирішення проблем)

### Проблема: Кирилиця відображається як "?"

**Рішення:**
1. Переконайтеся, що всі файли мають кодування **UTF-8 з BOM**
2. Перевірте наявність файлу `.editorconfig`
3. У Visual Studio: **File → Advanced Save Options → UTF-8 with signature**

### Проблема: Помилка компіляції "wchar_t not defined"

**Рішення:**
Додайте на початок файлу:
```cpp
#include <cstddef>
using namespace System;
```

### Проблема: "Matrix not initialized"

**Рішення:**
Спочатку встановіть ключове слово, натиснувши кнопку "Встановити ключ".

### Проблема: Некоректне дешифрування

**Можливі причини:**
1. Використано інший ключ для дешифрування
2. Зашифрований текст був змінений
3. У тексті є символи, які не входять в український алфавіт
